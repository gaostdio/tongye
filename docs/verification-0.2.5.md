# 0.2.5 大量图片互传与备份验证

2026-10-10。正式包名 `app.tongye.diary`，versionCode 8，versionName 0.2.5。APK 为 `deliverables/同页-0.2.5.apk`，19,962,511 字节，SHA-256：`70ef750b2b7f815f6e0431ebd3cdd9e12cb9e415ea4af6f309157e3bbc039ed2`。

## 问题与修改

用户确认「寄给 TA / 保存文件再发送」和「我的 → 导出数据与照片」在图片多时都无法导出。旧互传把照片、ZIP 和整份加密结果累计为字节数组，限制单图/单包 64 MiB、解压 128 MiB；旧备份也逐张 `readBytes`。图片增大时既会触发大小限制，又会造成大量内存分配。

- `ExchangeEngine.plan` 用文件流计算摘要，返回文件引用；产品寄件入口使用 `ExchangeFiles.prepare`，ZIP 直接进入最多 1 MiB 一段的 AES-256-GCM 输出。照片保持原始字节，摘要去重，不缩小或转码；移除旧 64/128 MiB 限制，新上限为 ZIP 和实际展开内容各 8 GiB，加密容器最多 8 GiB + 16 MiB。
- 新容器 `TONGYE3\n` 绑定每段序号、长度、随机前缀，必须有认证结尾并确认输入结束。接收完整认证后再打开磁盘 ZIP，限制路径、条目及实际展开大小，逐张校验照片 SHA-256，预览后才提交数据库；收下、取消或错误清理暂存。仍读取旧 `TONGYE2\n`，内部 bundle 仍写 2、读 1/2。
- `BackupFiles` 流式写 JSON 和原始照片，先在本机完成 ZIP，再以文件流写到系统所选位置。内容摘要命名避免不同目录下同名照片覆盖，相同内容只打包一次；没有互传的大小限制。默认不读取私密页的独占照片，明确勾选后才包含本人私密页，不含 PIN 或互传口令。
- 两个入口增加照片处理进度；设置页版本号读取已安装包版本，避免继续显示旧的 0.2.2。Room 仍为 2，未改变迁移、配对身份、合并、评论、私密、删除或确认规则。

## Android 15 隔离模拟器

使用已有自建 `tongye_test` AVD 的 Alice 正式安装和 Bob `.peer` 安装，先覆盖升级而未卸载。仅操作测试环境，没有连接用户手机。保存两个原始测试数据库快照；保留原口令、UUID、旧页面及评论，向 Alice 加入 12 篇公开测试页，每篇 10 张，共 **120 张 / 120 MiB**。

测试图片为有效 1×1 PNG 附带唯一随机负载，每张恰为 1 MiB，检验原始文件传输、内存和存储，不代表高分辨率相册显示压力测试。

1. 实际点击「寄给 TA」，FileProvider 临时授权将附件交给 Bob；预览显示「12 篇日记 · 120 张新照片」，收下成功。附件 **125,890,506 字节**，超过旧 64 MiB。Bob 数据库包含全部 12 页，120 张原图 SHA-256 全部匹配，原有页面逐项不变。
2. Alice 点击「保存文件再发送」，通过系统保存位置写入 Downloads，界面提示保存成功。文件 **125,890,506 字节**，与本机生成附件 SHA-256 同为 `353d247724997d889dc6e352f83c09288659e6fd70d98778ca7900c1f24e90b5`。
3. 「我的 → 导出数据与照片」默认未勾选私密，系统保存 ZIP 成功。备份 **125,883,674 字节**，ZIP CRC 检查通过，包含完整 12 页/120 张测试图片，逐张长度与 SHA-256 匹配；不包含私密页或配对秘密。
4. 最终正式 APK 覆盖安装后重新验证 ZIP 备份，结果一致，设置页显示 0.2.5；重新发送的新附件可被 Bob 完整认证并预览。点「稍后再收」后 Bob 的收件暂存目录为空，AndroidRuntime 未记录崩溃。
5. 测试后恢复两个原始虚构数据库，移除仅由本次生成的图片，关闭模拟器。辅助工具 `tools/check_large_photos.py` 在每次执行时强制确认 AVD 为 tongye_test。

## 升级、交接与边界

双方一起覆盖安装 0.2.5，保留现有日记、照片、PIN 和口令；更旧的 App 不能接收新 TONGYE3 容器。交接说明、协议、README、AGENTS 和推进清单已同步。用 `tools/package_handoff.py` 生成交接 ZIP，再用 `tools/verify_handoff.py` 检查 CRC、完整清单、逐文件 SHA-256 及 APK 摘要；包中带 43 项单元测试和 8 项低内存测试报告。

大图导出仍需要手机和目标位置留足存储空间。接收峰值包含解密 ZIP、解压暂存和最终图片；文件写入失败不会提交新的日记或确认寄件。目标保存位置若写入中断可能留下不完整文件，删除后可重试。8 GiB 是协议上限而非已实测容量，超过内容/大小上限尚不自动拆成多个附件。当前结果是 Android 模拟器和 JVM 验证，不是两台实体手机、真实微信/QQ 附件上限或所有低端机的证明；没有备份恢复功能。
