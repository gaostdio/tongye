# 本地交换说明

用户流程：昵称进入 → 一次性口令关联 → 寄出 .couple 文件 → 对方打开并确认收下。发送可使用系统分享菜单或先保存文件。部分聊天应用不能直接调用同页时，保存附件，再在同页选择文件。

## 身份与口令

两台手机分别生成并持久保存 UUID。共享口令由 SecureRandom 生成 128 位随机数，显示为 TY1 开头的可复制文本。双方使用相同口令；首次有效收件绑定另一人的 UUID，此后拒绝不同身份或不同接收身份的来件。没有服务器，也不采用邮箱、验证码或短数字密码。

口令只给另一半，是打开回忆的凭据。当前不提供解绑、换手机迁移或口令恢复界面，避免误把另一对情侣的数据混入；暂未实现备份恢复。

## 文件

0.2.5 寄出的文件以 `TONGYE3\n` 和 12 字节随机 nonce 前缀开始。ZIP 直接流式写入，按最多 1 MiB 一段进行 AES-256-GCM 加密，每段记录 4 字节大端明文长度、密文和 16 字节认证标签；结尾必须有长度 0 的认证记录，之后不允许多余字节。密钥仍由随机口令的 SHA-256 得到。每段 nonce 将前缀最后 32 位与序号异或，附加认证数据绑定格式、前缀、序号、长度。缺段、调序、篡改、截断或缺少结尾均拒绝；完整认证并确认文件结束后才处理临时 ZIP，不会把未验证内容交给收件预览。

接收将照片解压到本机隔离暂存目录，逐个验证 SHA-256，预览后才保存记录；取消、失败或收下后清理暂存。所有操作在后台执行，照片保留原始字节，不把整份图片集合放入内存。接收旧 `TONGYE2\n` 文件仍走旧格式的认证和大小限制；0.2.5 只寄新格式，双方应一起覆盖升级至 0.2.5，保留原口令和数据。更旧的 App 不能打开新格式。

ZIP 包含 manifest.json、diaries.json、removed.json 及 photos/。DIY 页面、元素与笔迹保存为日记里的结构化数据，不传 Android 代码。照片使用内容摘要命名，以 SHA-256 验证。

内部 bundle 在含视频的文件中写版本 3，其他文件写版本 2；兼容读取版本 1/2/3。版本 2 自 0.2.4 在 manifest 中加入 `commentUpdates`，用于个人页读者仅回传自己的评论；外层加密容器仍为 TONGYE3，0.2.6 视频扩展不改变评论与合并规则。

新格式的 ZIP 明文与实际解压内容各最多 8 GiB，加密文件最多 8 GiB + 16 MiB；生成时为文字和 ZIP 结构预留空间。每个 JSON 上限 32 MiB，每份文件最多 20,000 页日记/删除记录/评论更新、5,000 个照片摘要；条目数及单页画布元素数量另有限制。导入只允许固定名称和摘要照片路径，拒绝重复 ZIP 条目、任意路径、私密页、未知版本及无效人物信息。全部验证完成后才提交本机工作区；缺少图片时停止导入。以上只限制单次互传，不限制本机记录天数；超限文件尚不自动拆分，寄件版本不会因导出失败被确认或清空。

必须给手机留出临时空间：寄件缓存约占一份附件；收件需要解密 ZIP、解压照片和最终保存照片，峰值可能接近照片总量的三份。ZIP 备份先在本机完成，再流式写到选择的保存位置；手机缓存和目标位置都需要足够空间。备份不采用互传的 64 MiB/8 GiB 限制，照片按内容摘要命名，避免同文件名覆盖且相同内容只放一次。存储失败不修改日记，重新释放空间后可再导出；备份仍未加密且没有恢复界面。

## 动图与视频

0.2.6 支持 GIF 动图和手机可解码的视频。普通日记的 videos 列表与手账 VIDEO 元素携带视频引用，照片/GIF 仍使用 photos 和 IMAGE；统一按内容摘要放进 photos/<SHA-256>.bin，原始字节不变。包含视频的 bundle 必须为 3，禁止通过版本 1/2 偷带视频字段；旧 App 拒绝版本 3，双方需一起覆盖升级到 0.2.6。旧日记缺少 videos 字段按空列表处理，数据库结构和身份不变。普通页图片与视频合计每页最多 100 个，画布沿用 500 元素限制，所有附件共同计入 5,000 个摘要和原 8 GiB 上限。

GIF 按内容识别并自动播放，视频按明确类型生成封面、点开后在应用内播放，退出/后台停止；收件 .bin 后缀不会改变类型。共同回忆相册纳入视频。私密附件不会读取或寄出，备份只有明确选择本人私密时才纳入；正文只读、评论、增量确认、撤回与删除传播保留。无视频拍摄/剪辑/转码，播放格式取决于手机，不保证所有视频编码。

## 增量与可靠性

本机编辑递增版本，对方回信携带已收到的版本和照片摘要。寄出尚未确认的页面更新和删除记录，已经被确认的照片不再次发送。第一次或没有收到回信时，可能再次包含尚未确认内容；导入通过版本与页面 ID 去重。不会仅因用户打开分享菜单就假设对方已经收到。

历史已接收的照片确认摘要可持续积累；每份回信最多带最近 5,000 个，寄件方累加已知道的确认记录。遗漏于当前确认窗口的旧摘要最多造成重传，不会因为历史数量超限而使新回信无效。双方升级到 0.2.2 再交换大批量历史；旧版的单文件页数/JSON 上限较小。

「重新寄完整回忆」包含全部可交换页面与照片，用于补齐文件或照片。「保存文件再发送」与常规寄出一样生成增量文件。

## 三种可见范围

PRIVATE：永不进入互传文件，不读取其独占照片，也不能评论。PARTNER：正文和手账仅作者编辑，对方可阅读和评论；作者可在评论区回复。SHARED：双方可以续写及评论。旧示例页面排除在互传文件之外。

共享页改成私密后，寄出的是原页面 ID 的撤回记录，不包含新的私密正文或图片。对方已有的原始交换文件仍由对方持有。

打开自己的日记或共同手账，可用右上角「删除」或底部「删除这一页」。取消不会改动内容，确认后先保存删除结果，再离开详情；存储失败时留在确认界面供重试。删除自己的个人页或任一共同页会生成删除记录，下一次寄出、对方确认收下后生效；私密页删除不进入互传文件。寄出提示和收件预览都显示删除/撤回数量。删除被用作空间封面的手账时清空封面引用。照片原文件暂不清理，避免误删其他页面引用的照片。

共享画布按元素 ID 合并，不同元素可以并存。同一元素较新的时间优先，同一时间按稳定身份确定次序；删除元素及笔迹保留时间标记。页面文字、日期、背景等采用较新的整页版本。当前使用双方手机时间，严重的时钟差异可能影响冲突选择。暂无冲突历史选择界面。

0.2.4 在共同页及双方所有非私密日记/手账下方提供「评论」区。每条最多 200 字，每页最多 2000 条；本机保存成功后才清空输入，失败保留内容供重试。评论按唯一 ID 合并去重，并按日期、评论时间、ID 稳定排序；旧留言不带精确时间时显示原日期。发表评论只递增该页的寄件版本，不更新正文/背景的冲突时间。双方各自发表评论后交换文件，两人的评论可以共存；需下一次寄出、对方确认收下后可见。编辑中的旧草稿保存时也保留最新已有评论。仍不支持自动合并双方同时改过的共同正文，暂无评论编辑或删除。

个人页读者只回传本人追加的评论，通过 manifest 的 `commentUpdates` 标明页面 ID、所有者 UUID 和评论列表，不回传正文、布局或照片。接收时严格要求所有者为收件人、每条评论者为寄件人，检查 ID 去重、长度、时间和数量，并拒绝同 ID 既有整页又有评论更新的歧义。只对本机现有且本人拥有的非私密页追加，不更新正文时间；已删除或转私密的页面忽略评论，不能复活。个人页作者的回信仍带作者页面内容和已合并评论；接收作者页面时，即使正文时间相同也会合并评论，避免回复丢失。评论页计入寄件更新页数；回信确认后不重复寄出未改变的评论页。私密过滤和个人正文只读保护保留。

主题、昵称与指定的非私密 DIY 主页封面随文件传递。便签和额外纪念日当前只在本机。空间封面复用手账编辑器；后续再扩展独立主页设计。

## 开发验证

`-PtongyePeerTest=true :app:assembleDebug` 生成包名带 .peer 的第二个隔离测试安装，能在一个模拟器内验证两个身份、FileProvider 授权及来回交换。正式构建不加此参数。

参考 Android 官方 [FileProvider 临时文件授权](https://developer.android.com/training/secure-file-sharing/share-file) 与 [加密接口指导](https://developer.android.com/privacy-and-security/cryptography)。
