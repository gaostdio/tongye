# 0.2.2 长期使用验证

日期：2026-10-05。包名 `app.tongye.diary`，versionCode 5，versionName 0.2.2。正式 APK 在 `deliverables/同页-0.2.2.apk`，桌面副本为 `同页安装包.apk`。摘要附在 APK 旁；保持原签名，覆盖安装自动迁移 Room 数据库 1 → 2。

## 发现与修改

代码中没有试用期限、使用天数或本机篇数配额。之前全部日记放在 `workspace.json` 一行，长期增长会触及 Android CursorWindow 的单行读取限制；多个列表也会同时组成所有历史卡片。

当前每篇日记作为独立文档，超过 32,768 个 UTF-16 单元的文档再拆成小行，并避免拆断表情符号的代理对。资料及互传状态同样分段。旧大行通过 SQLite substr 小段读取，迁移写入成功后才在同一事务中清空旧行，不使用破坏性迁移。修改/删除只持久化变更文档，序列化及写入在后台执行，写入成功后才发布状态。

日记、个人空间、相册、时间轴、手账、纪念日、便签历史采用 LazyColumn；日记新增标题、正文、日期搜索及数量提示。互传扩大单文件文本历史容量，照片确认摘要采用有限的发送窗口，避免历史确认累积后造成新包无法接收。

## 构建与自动测试

`build.ps1 -Verify` 成功。24 项测试（ExchangeTest 17、ModelsTest 4、WorkspaceDocumentsTest 3），0 失败、0 错误；Lint 0 错误、12 条既有警告。

新增验证：

- 10,000 天的文本、私密页与身份从文档编码后完整还原。
- 单页手账超过 2 MiB，包含 100,000 个笔迹点及带表情的文字元素；小段不拆断代理对，还原后与原页一致。
- 在 10,000 篇档案中修改一篇，只写该页和资料；删除一篇只删除该文档并更新资料。
- 10,000 篇公开日记实际 AES-GCM 加密、解密、解析并合入对方；回信确认后下一天只寄一篇，再合入为 10,001 篇。
- 累计 6,000 个照片确认摘要仍能生成、打开并导入有效回信。

## Android 15 实际数据库与界面

使用独立 `tongye_test` AVD。全部数据均为虚构测试记录，未连接真实手机。

1. 覆盖安装普通旧库。迁移后的 3 篇日记、资料、配对身份及互传状态与升级前逐项相同。
2. 构造 Room 版本 1 的旧数据库：一行 JSON **22,950,220 字节**，含 **10,000 篇**日记，其中 **1,000 篇私密页**，日期跨 1999-05-21 至 2026-10-05。
3. 启动新版后自动迁移为 10,004 个小行，最大单行 JSON **32,768 字节**。逐条核对所有正文、表情、日期、可见范围及身份，完全一致；成功迁移后旧表为空。
4. 主页、日记列表可打开，显示 9,000 页非私密记录。重新启动后搜索 `Long-day-00002`，找到 1999-05-22 的旧页并正常修改保存。
5. 新增 2026-10-06 的 `Long-term-next-day`，强停并重启后仍可见。数据库实际为 **10,001 篇**，旧页修改仍在；其余 9,999 篇逐条与旧库相同，私密页仍为 1,000 篇。

核验脚本与结果：`deliverables/verification/longevity/check_storage.py`、`migration-result.json`、`continued-result.json`。脚本只允许拉取命名为 `tongye_test` 的模拟器数据库；测试库与生成数据不打包进 APK。模拟器最终恢复为原来的少量测试记录。

## 验证边界

这是大量数据及跨日期的模拟验证，不是已经经过数十年实用或所有手机的兼容测试。记录容量仍由手机空间、内存及单页复杂度决定；用户主动删除、清除应用数据、卸载或设备故障仍可能丢失数据，现阶段备份只支持导出。

单份互传文件仍限 64 MiB、单类 JSON 32 MiB、20,000 页记录/删除记录和 5,000 个照片摘要；超限不会清除本机日记，大量原图的完整重发尚不支持自动拆包。没有日记自动过期；七天清理仅针对可重新生成的寄件缓存文件。
