# 同页云端接入设计

当前 APK 是本地体验版。以下内容是后续接入方案，不表示双人同步已经完成。

## 数据与权限

Auth 为每个人提供独立 uid。私密数据放在 `/users/{uid}/privateDiaries/{id}`；共同日记放在 `/couples/{coupleId}/diaries/{id}`。私密日记的标题、正文、照片、数量都不进入情侣空间，也不写入共享统计。

情侣关系由受信任的 Cloud Functions 管理。客户端不能自行写成员列表、coupleId 或邀请绑定。每个情侣空间最多两个成员，每个用户最多一个活跃空间。

- `createCouple`：验证登录与用户当前关系；事务创建单成员空间和短期邀请码；邀请码使用加密随机数生成，服务端只保存摘要，禁止公开列举。
- `joinCouple`：校验邀请码摘要、有效期、发起者与加入者不同、成员数小于二、加入者没有活跃关系；在一个事务中更新情侣空间与两个用户的关系引用。并发加入时第二个请求必须失败。
- 邀请查询通过限速的可调用函数处理；不通过公开 Firestore 集合让客户端猜测或枚举。
- 成员读取共同数据；私密路径只接受拥有者 uid。Storage 同样校验身份与成员关系。
- 私密图片使用经过身份验证的 SDK 读取，避免持久公开下载链接或下载令牌泄露权限；缓存按 uid 隔离，退出登录时清除。

## 保存同步第一版

画布元素使用独立文档 `/couples/{coupleId}/diaries/{diaryId}/elements/{elementId}`。字段包括坐标、尺寸、缩放、旋转、图层、内容、createdBy、updatedBy、updatedAt。

保存时只写入实际修改的元素，`updatedAt` 使用服务器时间；同时修改同一元素采用最后成功提交的修改。同一页的不同元素不会因为整页快照覆盖而丢失。删除使用墓碑，防止离线旧客户端恢复已删除元素。`createdBy` 不可更改，`updatedBy` 必须是提交者。

独立日记正文使用版本号事务，冲突时提示用户保留哪一版，避免静默覆盖长文本。Presence 是独立的短期会话状态；只有读取到真实心跳时才显示「TA 也在这里」。Firestore 监听用于接收保存后的更新，随后再升级实时协作。

Room 本地快照需迁移成多表与 outbox。每次 Auth 身份变化重新校验访问权限，不能仅凭本地 coupleId 展示云端缓存；离线编辑应记录 pending 状态而不是显示已同步。

## 解绑与导出

解绑由服务端事务处理，不直接删除日记或 Storage 媒体。先导出共享内容、导出本人参与内容，再让双方确认规则，移除活跃关系。共有数据转成各自有权访问的归档，复制媒体或调整归档 ACL；本人私密数据不受影响。没有完成备份与归档前，不对历史内容执行自动删除。

## 上线前必须验证

Firebase Emulator 测试覆盖：匿名访问拒绝；第三人读取空间拒绝；伴侣读取私密文档、列表和媒体拒绝；uid 与 coupleId 篡改拒绝；共享照片上传后不能切换为私人路径；第三人竞争邀请码拒绝；最多两名成员；createdBy 不可伪造；解绑后旧成员关系不再允许写入；相册和统计不会包含私密信息。

规则草案采取默认拒绝，情侣成员只能由管理端创建；注册、邀请和解绑函数仍待实现。不可直接把草案当作完整的已审计后端上线。
