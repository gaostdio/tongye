# 0.2.3 评论功能验证

日期：2026-10-05。包名 `app.tongye.diary`，versionCode 6，versionName 0.2.3。正式 APK：`deliverables/同页-0.2.3.apk`。交付不再复制到桌面根目录。

## 修改与行为

原共同页下方的「写一句话」改为明确的评论区，包含评论数量、常驻输入框、200 字计数与「发表评论」，显示作者昵称和日期/时间。评论按可见项组成列表。保存成功后才清空输入，保存失败保留输入；共同日记和共同手账均可使用，个人只读页与私密页不开放。

评论单独追加，通过正常 `.couple` 增量文件寄出；对方确认收下后可见。`addComment` 递增寄件版本但不修改正文的 `updatedAt`、`updatedBy`、元素或背景，因此评论不会用旧正文覆盖较新的正文。按评论 ID 去重、日期/时间/ID 稳定排序；保存旧编辑草稿时保留已存在的新评论。新评论增加可选 `createdAt`，旧数据缺字段时为 0、显示原日期；沿用 Room 2 与原协议版本，不清库或重建身份。

正文的同时编辑冲突规则未改，仍可能按修改时间覆盖；本次没有实现正文冲突副本。评论目前每条 200 字、每页 2000 条，不支持评论编辑/删除。双方应升级至 0.2.3，旧版发表评论仍会更新页面时间，重新序列化也会丢弃精确评论时间。

## 构建与自动验证

`./build.ps1 -Verify` 成功，29 项 JVM 测试全部通过（ExchangeTest 22、ModelsTest 4、WorkspaceDocumentsTest 3），0 失败、0 错误。Lint 0 错误、12 条既有警告。

新增 5 项真实协议/状态测试：

1. 双方离线各自评论，在双向 AES-GCM 文件交换后保留两条、作者正确、顺序一致；重复收件不重复显示，增量包含评论页。
2. 一方改正文和标题，另一方在旧副本上发表评论；双向交换后均保留新正文与评论，即便评论发生时间更晚。
3. 使用缺少新评论的旧编辑草稿保存正文，已有评论仍保留。
4. 拒绝空白/超长评论、不存在页面、私密/个人只读页，以及超过单页评论上限的追加。
5. 不带新时间字段的旧评论可与新评论共存，并完成加密文件往返。

首次测试运行中有两份新增测试页面漏填标题，被现有文件校验正确拒绝；补齐测试标题后重新运行全部检查通过，未放宽原协议校验。

`apksigner verify --print-certs` 成功。证书 SHA-256 为 `442970906a708862e02e7bbd75b8eb5671c167529cca48b270892ca0cd36074a`，与此前版本一致，可覆盖原签名安装。APK SHA-256：`6483c3302c49053e6facb26636b11eaa1a0f6b152ec754b3c15ba4c9c547ca34`。
